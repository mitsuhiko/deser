# INI test corpus

INI has no specification and no shared conformance suite (like toml-test or
yaml-test-suite).  This corpus collects the test data of INI parsers in
various languages and configuration files of well known projects.  It is
vendored by `scripts/update-ini-test-data.sh`, do not edit by hand.  Every
directory has a `SOURCE` file with the pinned origin and the license of the
project it comes from.

Every parser implements its own dialect, so the expectations of one suite
only hold for that dialect.

## references/

How three widely used INI parsers read every input except the git config
ones (`scripts/ini/references/inputs.py` lists them):
`references/<input>.json` has the results of all of them side by side, a
variant that reads the input like the first variant of its parser is
written as `{"same_as": "default"}`.  The versions are in
`references/SOURCE`.

| Parser | Variants | Result |
|---|---|---|
| inih | `default` (multiline values, inline `;` comments, `;`/`#` comments), `no_multiline`, `no_inline_comments`, `allow_no_value`.  The limits on the length of lines and names are lifted | `events`: `["section", line, name]` and `["value", line, section, name, value]` in file order (duplicates included, `section` is `""` before the first header, `value` null without `=`), `error_line`: first line with an error or null (inih continues after errors) |
| Python's configparser | `default` (the stock `RawConfigParser`), `lenient` (`strict=False, allow_no_value=True, allow_unnamed_section=True`).  No interpolation, keys keep their case, input decoded as UTF-8 | `sections` and `entries` (`[section, key, value]`, last value wins) or `error` with `type` and `line` |
| PHP's `parse_ini_string` | `raw` (`INI_SCANNER_RAW`), `normal` (`INI_SCANNER_NORMAL`), sections processed, empty environment | `entries`: `[[key, ...], value]` leaves of the returned array (an empty section has the value `[]`) or `error` with `message` and `line` |

Strings that are not UTF-8 are stored as `{"hex": ...}`.

## suites/

| Directory | Parser | Expectations |
|---|---|---|
| `inih` | [inih](https://github.com/benhoyt/inih) (C), the minimal "classic" INI | `tests/baseline_*.txt`: handler calls (`[section] key=value;`) and the first error line per file, for the compile time options in `tests/unittest.sh` (multiline, inline comments, no value, ...) |
| `cpython-configparser` | Python's `configparser` | `captured/NNNN.ini` are all inputs of CPython's test suite, `NNNN.json` the parser options and the result (sections with key/value pairs or the error) of a fresh parser that preserves the case of keys. | `iniparser` | [iniparser](https://gitlab.com/iniparser/iniparser) (C) | `good_ini/` have to load, `bad_ini/` have to fail, values are checked in `test/test_iniparser.c` |
| `editorconfig` | [EditorConfig](https://spec.editorconfig.org/) parser tests | regular expressions in `parser/CMakeLists.txt` (combined with glob matching of the section names) |
| `npm-ini` | [ini](https://github.com/npm/ini) (JavaScript) | tap snapshots in `tap-snapshots/` (`a[]` arrays, quotes, `\;` escapes, dotted sections) |

### git config

git's own tests are GPL licensed and not vendored.  Instead the inputs come
from the test suites of other git config parsers and git itself is the
reference: `captured/NNNN.config` is an input, `NNNN.json` has the tests
that parse it and how `git config --list --null` of the pinned git (see
`SOURCE`) reads it, as `[section, subsection, name, value]` entries or an
error with the line.  git lowercases section and variable names, the
subsection is null for `[section]` and `""` for `[section ""]`, the value
null for a variable without `=`, the section null for variables before the
first section header.  See `scripts/ini/git-config/baseline.py`.

| Directory | Parser | How the inputs are collected |
|---|---|---|
| `gitoxide` | [gix-config](https://github.com/GitoxideLabs/gitoxide) (Rust) | gix-config's tests with the parser patched to record its inputs |
| `gcfg` | [gcfg](https://github.com/go-git/gcfg) (Go) | gcfg's tests with the parser patched to record its inputs |
| `go-git` | [go-git](https://github.com/go-git/go-git) (Go) | go-git's config tests with the patched gcfg |
| `dulwich` | [dulwich](https://github.com/jelmer/dulwich) (Python) | `tests/test_config.py` with `ConfigFile.from_file` patched |
| `jgit` | [JGit](https://github.com/eclipse-jgit/jgit) (Java) | string literals passed to `parse`/`fromText` and the value/subsection helpers of `ConfigTest` |
| `isomorphic-git` | [isomorphic-git](https://github.com/isomorphic-git/isomorphic-git) (JavaScript) | string literals passed to `GitConfig.from` |
